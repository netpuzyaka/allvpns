# AllVPNs

Мини-сервис для хранения VPN-конфигураций и раздачи их одной ссылкой.

- Главная страница — окно, где можно вставить конфиг (vless/vmess/ss/trojan-ссылки,
  можно списком) вручную или перетащить `.txt` файл (или выбрать его кликом) — его
  содержимое подставится в поле автоматически. Получаете короткий адрес вида
  `https://allvpns.vercel.app/vpn/a34fgf54d`.
- При обычном заходе на такую ссылку в браузере показывается страница-инструкция
  «эту ссылку нужно вставить в приложение Happ».
- При запросе от самого VPN-клиента (Happ, v2rayNG, Shadowrocket и т.п.) по тому же
  адресу отдаётся сырой текст конфигурации — как обычная ссылка-подписка.

## Как отличаются браузер и клиент

Next.js-роут `app/vpn/[id]/route.js` смотрит на заголовок `Accept` (браузеры при обычной
навигации отправляют `text/html`) и дополнительно на `User-Agent`. Это эвристика:
подавляющее большинство VPN-клиентов не посылают `Accept: text/html`, но если какой-то
клиент поведёт себя иначе, его тоже можно добавить в список известных user-agent'ов в
файле `app/vpn/[id]/route.js` (функция `looksLikeBrowser`).

## Хранилище — обязательно перед реальным использованием

Serverless-функции Vercel не хранят состояние между вызовами. Без внешнего хранилища
ссылки будут пропадать. Проект использует **Vercel Blob Store**:

1. В проекте на vercel.com → **Storage** → **Create Database** → **Blob**.
2. Подключите Blob Store к проекту (кнопка **Connect Project**) — Vercel сам добавит
   переменную окружения `BLOB_READ_WRITE_TOKEN`.
3. Сделайте **Redeploy** — без пересборки новая переменная не подхватится.
4. Без этой переменной сервис всё равно запустится и даже создаст ссылку, но
   использует временное хранилище в памяти процесса — оно годится только для
   локальной проверки интерфейса, не для реальной раздачи ссылок.

Каждая VPN-запись сохраняется как отдельный файл `vpn/<id>.json` в Blob Store и
читается обратно по тому же пути — в отличие от памяти процесса, Blob переживает
границы между функциями и холодные старты.

Локально переменную можно положить в файл `.env.local` (см. `.env.example`).

## Разработка

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

## Деплой на Vercel

1. Залейте этот проект в свой Git-репозиторий (GitHub/GitLab/Bitbucket).
2. На vercel.com → **Add New Project** → выберите репозиторий → Deploy.
3. Подключите базу данных, как описано выше, и сделайте redeploy.
4. Домен `allvpns.vercel.app` (или ваш собственный) — это и есть базовый адрес для
   ссылок вида `/vpn/<id>`.

## Структура проекта

```
app/
  page.js            — главная страница с формой добавления VPN
  api/create/route.js — создание записи и генерация id
  vpn/[id]/route.js  — выдача HTML-инструкции или сырого конфига
  globals.css        — оформление
lib/
  store.js           — хранилище (Vercel Blob + in-memory fallback)
  id.js              — генератор коротких id
```

## Заметка

Сервис — это просто хранилище текста по ссылке с двумя способами отображения.
Он не проверяет и не модерирует содержимое конфигов — ответственность за то, что
именно раздаётся по ссылкам, лежит на том, кто их создаёт и публикует.
